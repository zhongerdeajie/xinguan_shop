# ADR 0005: 为什么自然语言下单需要多步推理而不是一次性 LLM 调用

## 状态
已采纳（2026-07-27）

## 背景

用户输入："明天晚上 6 点要 4 个人的晚餐，预算 200，要 2 个荤 1 个素 1 个汤"。

LLM 需要：
1. 解析用户意图（人数 4、预算 200、时间 18:00、结构 2+1+1）
2. 查询菜品（多次工具调用）
3. 比价筛选
4. 加入购物车
5. 下单

## 评估方案

| 方案 | Token 消耗 | 准确率 | 响应时间 |
|---|---|---|---|
| A. 一次性 Prompt | 8000 | 60% | 3s |
| B. 单步 LLM + Tools | 3000 | 75% | 5s |
| C. 多步推理（LangGraph） | 4000 | **91%** | 8s |

## 决策

采用 **多步推理（LangGraph StateGraph）**（方案 C）。

### 推理流程

```
Step 1: 意图解析
  Input: "明天晚上 6 点要 4 个人的晚餐..."
  Output: {人数:4, 预算:200, 时间:18:00, 结构:2荤1素1汤}

Step 2: 查询候选菜品（多次工具调用）
  search_dishes(category="荤", max_price=80) → 8 个
  search_dishes(category="素", max_price=30) → 5 个
  search_dishes(category="汤", max_price=30) → 3 个

Step 3: 多条件过滤
  - 用户偏好（不辣）→ 过滤掉 2 个
  - 库存检查 → 标记 1 个已下架

Step 4: 比价组合
  组合 A (红烧肉 68 + 宫保鸡丁 72 + 清炒时蔬 28 + 番茄蛋汤 26) = 194 元 ✓
  组合 B (鱼香肉丝 58 + 麻婆豆腐 48 + 蒜蓉菜心 22 + 紫菜蛋花汤 18) = 146 元 ✓

Step 5: 询问用户确认
  展示两个组合，请用户选择

Step 6: 用户确认后下单
  add_to_cart() → create_order() → process_payment()
```

## 性能数据

| 步骤 | Token | 累计 |
|---|---|---|
| Step 1 解析 | 800 | 800 |
| Step 2 工具调用 | 1200 | 2000 |
| Step 3 过滤 | 600 | 2600 |
| Step 4 比价 | 800 | 3400 |
| Step 5 展示 | 400 | 3800 |
| Step 6 下单 | 200 | 4000 |

总 4000 token，比一次性 8000 token 节省 50%。

## 容错设计

- 任一步骤失败，可断点续传
- LLM 输出参数不合法，自动重试 3 次
- 用户可随时中断，调整需求
